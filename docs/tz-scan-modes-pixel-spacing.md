# Режимы 600/1200 dpi, Pixel Spacing и нарезка плёнки до 12 м

## Description

Оцифровщик радиографической плёнки (ширина 70 или 100 мм, длина до 12 м) должен сохранять снимок так, чтобы шаг пикселя в DICOM совпадал с оптикой камеры, а длинный рулон не собирался в один `cv::Mat` и в один кадр DICOM.

Оптика: кадр сенсора 1280×960, поле в плоскости плёнки примерно 27×20 мм. Номинальный шаг до измерения по линейке: **21 мкм** (около 1200 dpi). Режим оператора по умолчанию: объединение 2×2, шаг **42 мкм** (около 600 dpi). Требование заказчика по шагу — не крупнее 50 мкм. Значение `ppm = 36.571429` (27,3 мкм) в геометрию и в DICOM не подставлять.

Это задача про геометрию файла и два режима записи. Она не делает систему классом DS по ISO 14096-2: оптическая плотность, шаг 0,02 D и MTF в этот объём не входят. Профиль DICONDE (ASTM E2339) тоже не входит. Промежуточный контейнер — DICOM Secondary Capture, `Conversion Type = DF` (digitized film).

Ограничение DICOM: `Rows` и `Columns` — целые до 65535. При 21 мкм это около 1,39 м длины, при 42 мкм — около 2,77 м. Рулон 12 м сохраняется серией файлов с общими Study UID и Series UID.

## Acceptance Criteria

- В настройках сканирования есть режим: `bin = 1` (21 мкм, 1200 dpi) и `bin = 2` (42 мкм, 600 dpi). По умолчанию `bin = 2`.
- Шаг пикселя задаётся парой `pixel_um_x` и `pixel_um_y` в микрометрах. Пока нет замера по линейке, оба значения равны 21,0. Поле `ppm` не управляет ни шагом каретки, ни тегом DICOM.
- В каждом сохранённом файле есть теги: `SOP Class UID` = Secondary Capture Image Storage, уникальные `Study Instance UID`, `Series Instance UID`, `SOP Instance UID`, `Modality` = `OT`, `Conversion Type` = `DF`, `Photometric Interpretation` = `MONOCHROME2`, `Bits Allocated/Stored` = 16, `High Bit` = 15, `Pixel Representation` = 0, `Pixel Spacing` в миллиметрах.
- `Pixel Spacing` — пара «шаг по строке \ шаг по столбцу». При `bin = 1` это `pixel_um_y/1000 \ pixel_um_x/1000`. При `bin = 2` оба числа удваиваются.
- Режим `bin = 2` уменьшает каждый кадр вдвое по ширине и высоте усреднением окна 2×2 до сшивки. В файл не попадает прореживание «взять каждый второй пиксель».
- Плёнка длиннее одного кадра DICOM пишется несколькими файлами. У каждого `Rows` и `Columns` не больше 60000. У всех файлов одного скана одинаковые Study UID и Series UID, `Instance Number` растёт с 1. Имена: рядом с выбранным путём, суффикс `_001`, `_002`, …
- Скан не держит в памяти весь рулон 12 м. В RAM находится только текущий сегмент.
- Останов скана сохраняет уже записанные сегменты и не затирает их пустым изображением.
- Юнит-тест: усреднение 2×2 на синтетическом `CV_16UC1` даёт ожидаемые значения и удваивает шаг.
- Юнит-тест: изображение высотой больше 60000 строк в направлении подачи режется минимум на два DICOM, у каждого высота не больше 60000, Study UID и Series UID совпадают, `Pixel Spacing` записан.

## Technical Tips

- Точка записи шага — `saveToDcm` в `src/scanner/Utils.cpp`. Сейчас туда попадают только имя пациента, размеры и пиксели. UID брать через `dcmGenerateUniqueIdentifier` (DCMTK), как уже сделано в `include/tape_scanner/dicom_generator/DcmCreator.hpp`.
- `Pixel Spacing` (0018,1164): миллиметры, сначала соседние строки, затем соседние столбцы. Для этого сканера строки идут вдоль подачи роликов (Y), столбцы — вдоль каретки (X).
- Номинал до линейки: `pixel_um_x = pixel_um_y = 21.0`. После кадра с линейкой подставляются измеренные числа, формула `мкм = расстояние_мм / число_пикселей × 1000`, отдельно по X и по Y. В код замер не вшивать константой 27/1280.
- Биннинг до `Film::PushRegion`, в `Scanner::CaptureCadr`, после кропа `border`. Координаты `GetCurPixelCoords` делить на `bin`. Моторные шаги `camera_step_size` и `roller_step_size` не менять: поле кадра то же, мельче только сохранённая сетка.
- Усреднение 2×2 считать в `uint32_t` и делить на 4 с округлением, результат `CV_16UC1`. Так не режется хвост 12-битного сигнала, который сейчас растянут на 16 бит.
- Сегмент резать по границе шага роликов, не посреди тайла. Порог высоты сегмента — 60000 строк уже в сетке выбранного `bin`. При переполнении вызвать сохранение текущего `Film`, затем `Film::Reset` и продолжить скан в следующий файл.
- `Region::Expand` копирует весь холст при росте. Сегмент в 60000 строк при ширине 100 мм и 42 мкм — это около 2400×60000×2 байт ≈ 288 МБ на сегмент. Это верхняя граница RAM на текущую плёнку в режиме по умолчанию. Один холст на 12 м при 21 мкм (около 5 ГБ) не выделять.
- `Film::PushRegion` пишет PNG в `cadres/` на каждый тайл. Для этого ТЗ запись PNG убрать с пути скана: на рулоне 12 м она доминирует по времени.
- `Film::Reset` сейчас обнуляет локальные копии счётчиков. Починить, иначе нумерация тайлов и сегментов поедет после первого сброса.

### Description

Серия `_001`, `_002` должна складываться в одну плёнку без повторных строк перекрытия. Останов посреди прохода должен сохранять уже снятые тайлы незаконченной полосы и не дублировать её, если запись файла не удалась.

### Acceptance Criteria

- Высота `_001` плюс высота `_002` равна числу уникальных строк рулона. Строки перекрытия на границе сегментов во втором файле отсутствуют.
- В каждом файле есть `Image Position Patient (0020,0032)` = `0\offset\0`. `offset` в миллиметрах равен индексу первой строки сегмента, умноженному на шаг строки. У `_001` offset равен 0. Study UID и Series UID общие, `Instance Number` растёт с 1.
- Останов на полосе короче полной ширины сохраняет эту полосу в последнем файле вместе с уже сшитыми.
- Повторный `Finish()` после неудачного `saveToDcm` не вклеивает ту же полосу второй раз и не меняет уже записанные файлы.
- Подпись режима показывает `pixel_um * bin`. При 21,4 мкм и `bin = 2` на экране 42,8 мкм, в DICOM попадает 0,0428 мм.
- Юнит-тест на две полосы с перекрытием: суммарная высота без удвоенных строк, offset второго файла равен высоте первого, умноженной на шаг строки.
- Юнит-тест: полная полоса и следующая за ней более короткая обе есть в сохранённом кадре.

### Technical Tips

- В `ScanSession::Flush` сохранять строки `[0, next_y - m_y_origin)`. Последний `Finish()` не обрезать: хвост плёнки должен остаться.
- `m_y_origin` уже является глобальной строкой начала сегмента. В миллиметры переводить через `ScanGeometry::RowSpacingMm()`.
- `Film::GetMat` сейчас меняет холст и отбрасывает хвост при `pasted.width != m_all_stripes.GetRect().width`. Снимать кадр копией и включать короткую полосу всегда. `Reset()` вызывать только после успешного `saveToDcm`.
- Смещение писать из нового поля `DicomWriteParams` тем же `FormatDicomDecimal`, что и `Pixel Spacing`: `0\<offset>\0`.
- Текст комбобокса собирать из полей шага и выбранного `bin`, не оставлять зашитые «42 мкм» и «21 мкм».

Замер при 600 dpi файла, снятого на 1200 dpi, запишет шаг вдвое меньше. Кадр камеры RGB8 этим инструментом не открывается. |
| Указать X / Указать Y | Принято | Две левые точки. Считается только ось файла: X — столбцы (каретка), Y — строки (ролик). Поворот и отражение снимаются до подсчёта. Наклон линейки в диагональ не входит: её надо класть вдоль оси. Первая точка на экране не рисуется. |
| Запись в шаг и в следующий скан | Принято | «Записать X/Y» кладёт оптический шаг в поле мкм. Подпись режима умножает его на bin. Поле уходит в `settings.ini` и в `Pixel Spacing` следующего скана. На скриншоте запись ещё не нажата. |

Три положения каретки (центр и оба конца) по-прежнему снимает оператор: программа меряет один открытый кадр. Новое задание программисту не ставится.

### Description

Исходная постановка. Дефектоскопист открывает сегмент 16-битного снимка и крутит яркость так, чтобы видеть и светлую плёнку, и тёмный шов. Сейчас `DicomProcessor::GetCurFrame` вызывает `setMinMaxWindow()` и отдаёт в OpenGL уже пересчитанные DCMTK данные. Ползунки 0…65535 превращаются в долю `значение / 65535` и попадают в шейдер как центр и ширина окна в диапазоне 0…1. Старт 500/500 почти весь кадр уводит в чёрное или белое. Поворот и отражение записываются во флаги `open_file_rotation` и `open_file_flip` и на картинку не действуют.

Окно и уровень считаются по пикселям файла, до показа. Инверсия, масштаб 1:1 без размытия и тёмная сцена нужны, чтобы в лаборатории было видно пору, а не серое пятно.

### Acceptance Criteria

- В текстуру попадают значения `Pixel Data` без предварительного `setMinMaxWindow`. Ползунки Window Level и Window Width задают центр и ширину в тех же единицах, что пиксель файла: `low = center - width / 2`, `high = center + width / 2`.
- При открытии окно ставится на минимум и максимум кадра, и ползунки показывают эти числа, а не 500/500.
- Правая кнопка мыши: вертикаль меняет уровень, горизонталь меняет ширину. Колёсико увеличивает к точке под курсором. Левая кнопка двигает снимок.
- При масштабе 1:1 и крупнее фильтр текстуры `GL_NEAREST`. При отдалении допустим `GL_LINEAR`.
- Кнопка инверсии меняет смысл светлого и тёмного на экране и не переписывает файл.
- Поворот 0 / −90 / +90 / 180 и отражения по горизонтали и вертикали меняют изображение на экране.
- Листание `_001` / `_002` сохраняет выбранные уровень, ширину, поворот и инверсию.
- Юнит-тест или проверка шейдера: пиксель 1000 при центре 1000 и ширине 200 даёт середину серого; пиксель 0 при том же окне даёт чёрный; пиксель 2000 даёт белый.

### Technical Tips

- Убрать `setMinMaxWindow()` из `DicomProcessor::GetCurFrame`. Для показа брать `getOutputData` с окном на весь диапазон либо читать `Pixel Data` напрямую и не давать DCMTK применять VOI.
- В `fragment_shader.fs` центр и ширина приходят в нормированных единицах текстуры 0…1, но пересчёт из пикселей делать в одном месте: `center_norm = center / max_value`, где `max_value` для 16 бит равен 65535. Не делить номер ползунка на диапазон скроллбара второй раз.
- `GLImgViewer` уже кладёт `CV_16UC1` в `GL_LUMINANCE16`. Для контекста OpenGL 3.3 надёжнее `GL_R16` и выборка `.r`. Фильтр min/mag переключать в `SetImage` или при смене масштаба.
- Поворот и отражение — матрица текстурных координат или `cv::rotate` / `cv::flip` перед загрузкой тайлов. Флаги в `MyMainWindow` после этого должны вызывать перерисовку, а не только запоминать угол.
- Инверсия в шейдере: `shown = 1 - shown` после окна, до записи в `FragColor`.
- Не писать эти преобразования обратно в DICOM. Файл остаётся сырым.
